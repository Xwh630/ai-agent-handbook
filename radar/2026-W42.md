## 🔥 头条：上下文工程正在从方法论变成货架商品

上周我们在第 2 期讲「上下文工程成为独立学科」。这周，它有了商品形态。

| 项目 | Stars | 日增 | 它卖的是什么 |
|------|-------|------|-------------|
| [thedotmack/claude-mem](https://github.com/thedotmack/claude-mem) | **96,221** | +534 | 跨会话持久记忆：捕获每次会话的编辑/决策/报错 → LLM 压缩 → ChromaDB 索引 → 下个会话语义召回。**支持 Claude Code / Codex / Gemini / Copilot / OpenCode 等 7+ 平台**，记忆格式标准化后可跨平台复用 |
| [mksglu/context-mode](https://github.com/mksglu/context-mode) | — | +190 | 上下文窗口优化器：把工具输出沙箱化，**削减 98%**，通过 MCP 路由到 17 个平台 |
| [VictorTaelin/OptMem](https://github.com/VictorTaelin/OptMem) | — | +85 | 极简方案：**一个 426 token 的即插即用提示词 + 脚本**，做永久记忆 |
| [garrytan/gstack](https://github.com/garrytan/gstack) | — | +286 | 另一个思路：不优化上下文，而是**重新分配角色**——23 个工具分别扮演 CEO、设计师、工程经理、QA |

### 三个项目，三种哲学

```
claude-mem      「存起来」  → 压缩 + 向量检索，靠 infra 解决
context-mode    「别进来」  → 工具输出根本不进上下文，靠隔离解决
OptMem          「写下来」  → 一个 426 token 的约定，靠 prompt 解决
gstack          「分开搞」  → 按角色拆 Agent，靠架构解决
```

> 💡 **这张图值得多看你一眼**：它正好对应本手册**第 27 章**讲的三板斧——
> `Compaction`（claude-mem 的压缩链路）、`Structured Note-taking`（OptMem 的持久化约定）、`Sub-Agent 架构`（gstack 的角色拆分）。
>
> **方法论和商品几乎同时出现，这在技术领域是很少见的。** 通常学科成熟要几年，产品化再要几年。这次几乎同步——因为痛点太硬了。

### 一个反直觉的对照

`OptMem` 用 **426 token** 做到了 `claude-mem` 用 ChromaDB + SQLite + LLM 压缩链路做到的事的一部分。

**这不说明谁更优，而是说明这个市场还没分层。**

- 需要跨 7 个客户端、语义检索、团队共享 → 重型 infra 值得
- 只是想让 Agent 记住项目约定 → 426 token 够用

> ⚠️ **选型提醒**：不要因为某个项目星多就上重型方案。先问自己——**我的上下文痛点具体是哪一个？** 第 27.3 节那张 token 构成表，就是你回答这个问题的工具。

**以及一个实验：**

我们把整本手册打包成了一个符合规范的 Agent Skill 包 —— [`skills/agent-handbook/SKILL.md`](../skills/agent-handbook/SKILL.md)。装进 Claude Code 等客户端后，你在对话里问 Agent 相关的问题，它会自己去翻对应章节。

**这个包的编写严格遵循了第 26 章自己的规范，并且用附带的校验器跑过：**

```
$ python3 examples/10-agent-skill/main.py skills/agent-handbook
通过 5  错误 0  警告 0  提示 2
✅ 全部通过，可以发布。
```

> 手册推荐的规范，手册自己遵守。**这是自我论证的最小成本方式。**

配套还有一个工具：[`examples/10-agent-skill/`](../examples/10-agent-skill/README.md) —— 第 26.10 节自检清单的可执行版本，一次跑完 20+ 项检查，零第三方依赖，可直接接 CI。

## 💬 本期一个值得思考的问题

`claude-mem` 的记忆格式做了标准化，**在 Claude Code 里积累的记忆，可以在 Codex 会话里被调用**。

这件事有两面：

- 好的一面：你的 Agent 经验终于可以跨平台迁移，不再被单个客户端绑架
- 另一面：**你的工作习惯、项目上下文、甚至犯过的错，正在被写进一个可迁移的文件**

> **如果记忆可以跨平台迁移，那它就一定可以被复制、被同步、被上传到别人的服务器。**
> **你愿意让 Agent 记住你多少东西？这条线你画在哪——记住项目约定可以，记住你的代码习惯呢？记住你调试时的思考路径呢？**
