    💬 Discussions 使用指南（维护者配置 + 现成帖子）¶

    现状（2026-10-30 实测）：仓库已开启 Discussions 能力，但分类未建、帖子数为 0。 README 里两处 CTA 都指向这个空页面——等于把流量倒进黑洞。这份文件把它填上。

    注意：GitHub 没有通过 API 创建 Discussions 分类的公开接口，分类必须手动建（约 3 分钟）； 帖子可以在网页上粘贴本文件的现成内容，一篇约 1 分钟。

    一、建三个分类（Settings → General → Features → Discussions → 齿轮）¶

    分类名 Emoji 格式 用途
    Q&A 💬 Question / Answer 提问必须能被"采纳答案"，这是唯一能沉淀质量的格式
    体检墙 🩺 Open-ended discussion 贴 handbook doctor 分数，互相看短板
    Show and tell 🙌 Open-ended discussion 读者项目展示，Radar「社区精选」从这里取材
    Radar 📡 Announcement 每期周刊的讨论帖（Announcement 只有维护者能开新帖，防噪音）

    建议顺序：Q&A → 体检墙 → Show and tell → Radar。第一条必须是 Q&A，因为它是默认分类。

    二、四条现成帖子（直接复制粘贴）¶

    帖子 1 · 置顶：体检墙（发在「体检墙」分类）¶

    标题：你的 Agent 项目，五根柱子齐了几根？——贴出你的 doctor 分数

    正文：

    这是一条**永久置顶**的帖子。规则只有一条：**贴分数，不贴吹捧。**

## 怎么拿分数

```bash
uvx agent-handbook doctor .

    不想装东西？pipx run agent-handbook doctor . 或者 pip install agent-handbook 都行。

    贴什么¶

    项目 分数 最缺的柱子 我打算怎么补
    我的客服 Agent 4/10 失败恢复 先加 L2 重试 + 降级
    我司内部工具 7/10 权限体系 排期到下个迭代
    • 项目链接可以不贴（不想公开就写"某内部项目"）
    • 最缺的柱子一定要写——那是这张表最有信息量的一列
    • 想让人帮你看看，把 handbook doctor . --md 的输出贴进来

    为什么值得贴¶

    第 25 章讲的东西人人都懂，但没有人会拿文章去对照自己的 800 行 main.py。 分数的作用不是评价，是定位：它告诉你该先补哪一根，而不是"你不合格"。

    参考分布：我们跑过的项目里，绝大多数落在 2–5 分之间。3 分不是你差，是行业常态。

**正文**：

```markdown
欢迎提问。为了让你更快拿到答案，麻烦带上这三样：

1. **你跑过哪条命令 / 打开哪个文件**（例如 `handbook doctor .` 的输出，或 `chapters/25-harness-engineering.md` 的 25.4 节）

3. **你已经试过什么**

如果你连从哪一章开始都不确定：

```bash
handbook search 你的关键词

    它会直接给出章节 + 行号 + 片段。

    维护者响应承诺：工作日 24 小时内必回；周末可能延迟到周一（在校生，见谅）。

    不确定是不是 bug？ 也可以直接发在这里，不用纠结该开 Issue 还是 Discussion。

### 帖子 3 · Show and tell（发在「Show and tell」分类，置顶）

**标题**：用这本手册做出了什么？贴出来，下一期 Radar 的「社区精选」留了位置

**正文**：

```markdown
这个分类的每一篇，都会被 Radar 周刊的固定栏目「社区精选」看到。

## 格式（照抄，不要自由发挥）

**项目名** · `GitHub用户名-项目名`

- **一句话**：它解决什么问题
- **仓库**：（可留空）
- **用到的章节**：第 X 章 · 第 Y 章
- **体检**：`handbook doctor . --md` 的输出
- **踩过的坑**：一句你最想对后来的读者说的话

## 收录后会发生什么

1. 进 `projects/` 目录（提 PR 即可，模板在里面）
2. 被写进下一期 Radar 的「社区精选」
3. 你的名字出现在 README 的致谢墙

> 为什么做这件事：一个人写 31 章，天花板是 31 章；
> 十个人各写一个项目，天花板是**十个真实场景**。后者才是读者真正需要的东西。

    帖子 4 · 进阶内容投票（发在 Q&A 或新建「Roadmap」分类，不要置顶）¶

    标题：如果只能做一个"付费/进阶"内容，你最想要哪个？（2 周后统计）

    正文：

    免费层（31 章 + 11 个示例 + CLI + Radar）永远完整，这点不变。

但维护是有成本的，我想知道**哪一项最值得做**。请只选一个，并在楼下写一句"为什么"：

- **A. 生产级模板库**：编排 + Harness + 评测三合一的现成项目骨架
- **B. 行业评测集**：客服 / 数据 / 代码三个场景的私有 rubric + 样本
- **C. 项目 Review**：我给你那个项目做一次 doctor 深度体检 + 改进方案
- **D. 都不要**，请把时间留给定期的免费内容

> 这条帖子的用途有两个：一是搞清楚需求，二是**验证有没有人愿意为它付费**。
> 如果连"想要"都凑不齐 30 条回复，那就不该做——这是最便宜的市场调研。

    三、发完之后要做的三件事¶

    1. 回填 README：确保 README.md 里指向 Discussions 的链接落到 Q&A 或置顶帖，而不是空列表页。
    2. 每期 Radar 开一条 Discussion：标题 Radar 第 N 期讨论，正文只放一句「本期你最不同意哪一条？」——讨论量比星数更能说明内容是否被读。
    3. 每周五复盘：记录 3 个数字（本周新增帖子 / 外部参与者 / 体检墙新增分数）。如果连续两周为 0，问题不在 Discussions，在流量——那就回去做分发（见诊断报告 P1）。

    四、一个反直觉的提醒¶

    Discussions 开起来之后，最可能发生的是：还是没人发帖。

    这很正常，而且不是 Discussions 的问题。社群是流量的结果，不是流量的原因。 所以这份指南的正确用法是：先把分类和置顶帖铺好（成本 15 分钟），然后不要盯着它看，去做分发。 等第一批外部访客进来时，他们看到的至少不是一个空白页。
